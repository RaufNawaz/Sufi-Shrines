# OCR on a new machine — copy the folder, run three commands

**Written 11 September 2026** for the 42 new books Adil Ahsan and Saifullah Imtiaz uploaded
through the Google Form between 29 July and 17 August 2026. The MacBook Air thermal-throttles,
so the OCR batch moves to a machine with more memory and a GPU. This is the whole procedure, in
order. Everything it refers to is in the repository; nothing has to be remembered.

It supersedes `NEW_LAPTOP_OCR_RUNBOOK.md` (9 August 2026, written for two books and the M1 Pro)
for the *OCR* part. The two older references still hold for every flag:
`BOOK_OCR_WORKFLOW.md` (Windows) and `BOOK_OCR_WORKFLOW_MAC.md` (macOS).

## 1. On the Air — copy the folder, not a clone

`books/` and `out/` are **gitignored**. A `git clone` on the new machine would bring the tools
and none of the 30 finished transcriptions, so the batch would redo all 6,357 pages of July.
Copy the folder.

```bash
cd ~/Harvard    # or wherever the project lives; see CLAUDE.md RULE 1 for the two look-alike folders
du -sh "Shrines Project"/books "Shrines Project"/out      # 11 Sep 2026: 1.2G and 35M
rsync -avh --progress --exclude node_modules --exclude .venv --exclude dist \
  "Shrines Project"/ /Volumes/<DRIVE>/"Shrines Project"/
```

Optional, saves a 95 MB download and a clone: also copy the sibling
`End-To-End-Urdu-OCR-WebApp/` folder (the UTRNet server with its weights already in it). Its
`.venv` is machine-specific and the setup script rebuilds it.

Commit first if anything in the repo is uncommitted (`git status --short`); the copy carries the
working tree, but the commit is what makes it recoverable.

## 2. On the new machine — one script installs everything

```bash
cd "Shrines Project"
bash tools/setup_ocr_machine.sh --dry-run      # reports OK / MISSING for every prerequisite, changes nothing, exit 2 if anything is missing
bash tools/setup_ocr_machine.sh                # installs what was missing, sets up both virtualenvs, fetches the model weights
bash tools/setup_ocr_machine.sh --dry-run      # should now print "All prerequisites present." and exit 0
```

Windows: `powershell -ExecutionPolicy Bypass -File tools\setup_ocr_machine.ps1 -DryRun`, then
without `-DryRun`. (The PowerShell twin was written on a Mac and has not yet been run on Windows;
its winget ids are the ones `LIBRARY_OCR_SETUP.md` used successfully.)

What the script does, and checks before doing:

1. **System tools** — git, curl, Poppler (`pdftoppm`, `pdftotext`), Tesseract. Homebrew on
   macOS, apt on Debian/Ubuntu, winget on Windows. Urdu and Persian Tesseract data ship in the
   repo's `tessdata/`; English data comes with the Tesseract package.
2. **Project venv** — `.venv` from `requirements.txt` (pillow, gdown, gradio_client, openpyxl).
3. **UTRNet OCR server** — clones `github.com/abdur75648/End-To-End-Urdu-OCR-WebApp` as a
   *sibling* of the project folder, builds its venv on **Python 3.10** (the app's torch/gradio
   pins need exactly that), installs its requirements, then force-installs the pinned web stack
   from `tools/utrnet-pins.txt` (the app does not run on current Gradio), then downloads the
   five model files from the HuggingFace Space `abdur75648/UrduOCR-UTRNet`
   (`best_norm_ED.pth` 42.9 MB, `yolov8m_UrduDoc.pt` 52.1 MB, three sample JPGs — verified
   reachable 11 Sep 2026) and refuses to finish if either model file is under 40 MB.
4. Prints the commands below with the real paths filled in.

Re-running it is safe; it only installs what a check finds missing. On an NVIDIA machine, if it
prints `CUDA: False`, install the CUDA wheel from pytorch.org into the UTRNet venv — CPU OCR is
roughly ten times slower. On Apple Silicon it reports `MPS` instead.

## 4. Download the books (second terminal)

The files are private, so give `gdown` a logged-in session once. In a browser signed in to the
account that can open the Drive folder, install a "Get cookies.txt LOCALLY"-type extension and
export `cookies.txt` for `drive.google.com`. Then:

```bash
cd "Shrines Project" && source .venv/bin/activate
python tools/download_books.py --links pipeline/books_links_2026-09-11.txt \
  --out books/incoming-2026-09-11 --cookies ~/Downloads/cookies.txt
```

- 42 files, 1.36 GB. Six *Masnavi* volumes are 50–105 MB each; the whole run is minutes on a
  fast connection. Re-running skips what is already down (`books/incoming-2026-09-11/manifest.json`).
- Then sort and verify:

```bash
python tools/books_manifest.py --sort-downloaded   # moves the 23 English PDFs + EPUB to books/incoming-2026-09-11-english/, prints the HOLD file
python tools/books_manifest.py --verify            # checks every file's size against Drive, writes sha256 into pipeline/books_manifest_2026-09-11.tsv
```

`--verify` exits non-zero on any size mismatch or missing file. Do not start OCR on a folder that
failed it. Then deal with the one HOLD: open `revisedtranslati00nizauoft` and move it to the
`-english` folder if it is English.

If cookies are a nuisance: open the Drive folder in the browser, download it (Drive zips it),
unzip into `books/incoming-2026-09-11/`, delete the three duplicates by hand, and run
`--sort-downloaded` / `--verify` as above — they read filenames, so this works without
`manifest.json` only partially: `--verify` needs the download manifest to map files to ids.
The cookies route is the one that verifies.

## 5. Run the OCR (same terminal)

```bash
bash tools/run_new_books_ocr.sh                   # everything, routed
bash tools/run_new_books_ocr.sh --max-pages 3     # smoke test first: three pages of every book
```

`run_new_books_ocr.sh` does, in order: EPUB extraction; `ocr_all_books.py` over
`books/incoming-2026-09-11/` against the local UTRNet server (it refuses to start if the server
is not up); then `ocr_all_books.py --ocr-engine tesseract` with `TESSERACT_LANG=eng` over the
`-english` folder, where the embedded text layer is extracted first and only true page images go
to Tesseract. Every step skips books that already have `out/ocr/<book>/p001-end_*_transcribed.txt`,
so an interrupted run is resumed by running it again. Extra flags pass through to
`ocr_all_books.py` (`--workers 2`, `--dpi 200`, `--split-spreads` for two-page-spread scans —
July found seven of thirty needed it, and the symptom is lines from two pages interleaved).

Progress: `python tools/ocr_status.py` writes `out/ocr/STATUS.md` (per-book page counts and an
ETA; run it in a loop, it is atomic).

**How long.** The only measured rate is July's: the GPU laptop's status tool assumes
**2.2 s/page** (`tools/ocr_status.py`, `FALLBACK_SECONDS_PER_PAGE`), and the overnight mop-up
did 19 books in 6 h 31 m. The 17 new scans are 877 MB; at the July corpus's density
(253 KB/page across 4,665 measured pages) that is roughly **3,500 pages ≈ 2 hours of OCR** on a
comparable GPU, several times that on CPU. Get the real page count once the files are down:
`pdfinfo file.pdf | grep Pages`. The 23 English PDFs are seconds each when the text layer is
usable; Rizvi and *Walking with Nanak* may be 1–3 hours of Tesseract if they are page images.

## 6. Bring the results back

Copy `out/ocr/` back onto the Air (or wherever the archive is edited) — it is the only output,
and it is gitignored, so it travels by copy, not by git:

```bash
rsync -avh --progress /Volumes/<DRIVE>/"Shrines Project"/out/ocr/ ~/Harvard/"Shrines Project"/out/ocr/
```

Also copy back `pipeline/books_manifest_2026-09-11.tsv` (the `--verify` columns) and
`books/incoming-2026-09-11*/` if the Air should hold the PDFs too (1.36 GB; optional).
Commit the manifest TSV — it is the record of what was downloaded and hashed.

**What `finalize_books.py` will and will not do.** It publishes verified transcriptions to
`out/ocr/Final/` under human-readable names, but its per-book table (`BOOKS_INFO`: page count
and script) is hard-coded for the 30 July books and **it silently ignores any book not in it**.
For the new books either add rows (page count from `pdfinfo`, script `arabic` or `latin`) and a
`books/renames.json` entry per file, or review by hand from
`out/ocr/<book>/p001-end_*_transcribed.txt`. Then the existing flow: `tools/ocr_postcorrect.py`,
translation drafts, `tools/summarize_books.py` — see `BOOK_OCR_WORKFLOW.md` §§ 5–10.

## 7. Known gaps, stated rather than hidden

- **Nothing was downloaded on 11 September 2026.** All 42 files are private to the Drive
  account; anonymous `curl` and `gdown` both land on a sign-in page. Step 4 is the first thing
  the new machine does.
- **`setup_ocr_machine.ps1` is untested on Windows.** `bash -n` and a real `--dry-run` were run
  for the shell twin only.
- **`revisedtranslati00nizauoft`** is unidentified until someone opens it.
- **Page counts are an estimate** until `pdfinfo` runs on the downloaded files.
- The UTRNet weights come from a third-party HuggingFace Space that could disappear. If the
  sibling folder was copied from the Air in step 1, the weights are already present and the
  script skips the download.
